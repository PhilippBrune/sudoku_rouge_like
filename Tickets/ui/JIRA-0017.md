# JIRA-0017 — UI Polish, Overlay Fixes, Boss Logic, XP Loop & Graph

**Created:** 2026-03-09

## Summary

16 follow-up fixes after JIRA-0016 completion, covering overlay rendering, boss mode logic, XP display, graph connectivity, and UI layout.

---

## Requirements

### R1 — Main Menu Buttons: Perfect Background Overlap
- Transparent buttons in main menu must precisely overlap the button graphics in the background image.
- Align anchors/offsets to match the exact pixel positions of the background button visuals.

### R2 — Transparent Buttons: Main Menu Only
- Transparent button style must only apply in the main menu.
- In-run and all other screens: buttons retain normal (non-transparent) styling.

### R3 — Fog: Placed Number Visible
- When a number is placed in a fogged cell it must be rendered visibly to the player (not hidden by fog overlay).
- The fog visual must render behind the number layer.

### R4 — Arrow Sum: Unfilled Circle for Target Cell
- The target (bulb/circle) cell of an arrow sum should display an unfilled (hollow) circle outline, not a filled circle.

### R5a — Parity Lines: Distinct Colour
- Parity line colour is too similar to the row/column highlight colour.
- Choose a clearly distinct colour for parity lines (e.g. bright teal or lime green).

### R5b — Kropki Dots: Filled Circle (not square)
- Both White Dot and Black Dot Kropki mechanics currently render a square.
- Replace with a filled circle (using `Image` with a circular sprite or `sprite = null` + round corners, or draw via UI mesh).

### R6 — Killer Cage NullRef (line 4433)
- `NullReferenceException` in `BuildModifierOverlays` at line 4433.
- Previous fix (AddComponent<Text>) did not take effect. Re-examine and fix root cause.
- Killer cage must render: dashed outline around cage cells, sum label in top-left corner.

### R7 — HP and Pencil Graphics
- Add a graphical bar/pip display for HP and Pencil charges.
- HP bar: filled proportion = `CurrentHP / MaxHP`.
- Pencil pips: filled pips = `CurrentPencil / MaxPencil`.

### R8 — Irregular (Jigsaw) Region Layout
- Implement jigsaw region layouts for 6×6, 8×8, and 9×9 board sizes.
- Each layout must partition all cells into N groups of N cells (where N = board size), each group contiguous.
- Add at least one pre-defined layout per size.

### R9 — Shop / Relic / Rest Nodes: Remove Size and Stars Labels
- Shop, Relic, and Rest path nodes must not show the Size (top-left) and Stars (bottom-right) labels.
- Only Puzzle nodes should show those labels.

### R10 — Boss Gate: Last Path Tile Connection
- The last tile of the left path and the last tile of the right path are not connected to the Boss Gate tile.
- Fix: connect last-left to the left edge of the Boss Gate; connect last-right to the right edge of the Boss Gate.

### R11 — Replace Mechanic Buttons: No Overlap
- Buttons for choosing the Replace mechanic currently overlap or touch each other.
- Add spacing so buttons do not touch.

### R12 — XP Loop: Still Broken
- After a run, `MetaProgressionPanelController` still shows `0/120 XP` and no level-up.
- Verify `ClassGardenProgressionService.ApplyRun` is called with the correct `ClassId` and XP is persisted/reloaded.
- `RefreshView` must read from the saved profile (not an in-memory default).

### R13 — Boss Description: All Active Modes
- Boss mode description text must list **all** active boss modifiers, not just the first one.
- One line per active modifier.

### R14 — Boss Fight: One Active Mode Only
- The boss fight must only activate the single mode the player chose before the run.
- No additional modifiers should be injected.

### R15 — Boss Mode Appearance Count ≥ 1
- If a boss mode is selected, its appearance count within the puzzle must be ≥ 1 (never 0).

### R16 — Resume Game: Grayed Out When Unavailable
- "Resume Game" button must be grayed out (non-interactable) when no saved run is available.
- Tutorial runs are not resumable; Resume must be grayed out after a tutorial run.
