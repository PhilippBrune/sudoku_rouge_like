## Requirements

### R1 — Main Menu Buttons: Transparent

**Problem:** Main menu navigation buttons (Start Game, Resume, Tutorial, etc.) have an opaque blue-grey background. The buttons should be visually transparent so only the text, icon, and accent outline are visible.

**Root Cause:** `BuildButton` applies `buttonColor` (alpha ~0.94) to all buttons. `BuildMenuButton` did not override this.

**Solution:** In `BuildMenuButton` (`MainMenuBlueprintBuilder.cs`), after calling `BuildButton`, override the `Image` color to `alpha=0` and replace the `ColorBlock` with transparent-normal (0% opacity), 8% white on hover, 12% dark on press, `colorMultiplier=1`.

**Files:** `Assets/Scripts/UI/MainMenuBlueprintBuilder.cs`

### R3 — XP Balance: Pacing Too Fast, Level Display Missing

**Problem (a):** Level-ups happened after 1-2 puzzles. `ClassGardenProgressionService.XpToNextLevel` started at 120 XP, increasing 20 per level. With `XpService` giving 50-400 XP per puzzle, players leveled up immediately.

**Problem (b):** Class level and XP were not visible in Class Select or Meta Progression screens (user reported).

**Solution (a):** Raised thresholds — L1 now costs 500 XP, increasing by 100 per level up to L20 (L20 costs 2400), then quadratic acceleration beyond L20. A typical 9×9 2★ puzzle gives ~150 XP, requiring ~3-4 puzzles per early level-up.

**Solution (b):** Class Select already showed `Level {entry.Level} | XP {entry.CurrentXp}/{xpToNext}` in `RefreshClassSelectUi`. Meta Progression:
- Added "Garden Level: X  XP: Y/Z" line to the summary panel (`MetaProgressionPanelController.RefreshView`)
- Fixed stale hardcoded `"Level 1 | XP: 0/120"` fallback — now reads from `XpToNextLevel(1)` dynamically

**Files:** `Assets/Scripts/Meta/ClassGardenProgressionService.cs`, `Assets/Scripts/UI/MetaProgressionPanelController.cs`

### R4 — Boss Modifier Choice Not Applied in Normal Run

**Problem:** After selecting a boss modifier from the gate panel, the chosen modifier was not active during the boss puzzle. The modifier was correctly applied in Tutorial mode but not in Garden Run mode.

**Root Cause:** `RunMapController.GetFixedLevelConfig` caches level configs when the path is first previewed (before the player sees the boss gate). `ChosenBossModifier` is set AFTER the cache is built. When the puzzle launched, it returned the stale cached config (without the modifier).

**Solution:** After returning the clone from cache, check if the node is a Boss node and `RunState.ChosenBossModifier` is set. If so, add it to the cloned config's `ActiveModifiers` before returning. The cache itself is not modified — only the returned clone.

```csharp
// After: var result = CloneConfig(config);
if (node.Type == NodeType.Boss && _run.RunState?.ChosenBossModifier.HasValue == true)
{
    var chosen = _run.RunState.ChosenBossModifier.Value;
    if (!result.ActiveModifiers.Contains(chosen))
        result.ActiveModifiers.Add(chosen);
}
return result;
```

**Files:** `Assets/Scripts/UI/RunMapController.cs`

### R5 — Irregular Puzzles Toggle in Class Select

**Problem:** Players had no way to opt out of jigsaw/irregular region layouts during a normal run. Once `AllowIrregularPuzzles` was always true, every run included irregular puzzles.

**Solution:**
- Added `public bool AllowIrregularPuzzles = true;` to `RunState` and `LaunchRequest`

- Added "Allow Irregular Puzzles" `Toggle` (`TglAllowIrregular`) to Class Select panel (anchored at 4%-50% width, 5%-14% height)
- Toggle starts checked (true), wired to `MainMenuController.SetAllowIrregularPuzzles(bool)`

### R6 — Modifier Overlay Circles: Knob.psd Runtime Error

**Problem:** All circle-based modifier overlays (Parity Lines dots, German/Dutch Whispers dots, Difference/Ratio Kropki, Arrow Sum bulb) produced spam errors every frame and failed to render correctly:
```
The resource UI/Skin/Knob.psd could not be loaded from the resource file!
UnityEngine.Resources:GetBuiltinResource<UnityEngine.Sprite>(string)
PrototypeRunScreenController:DrawOverlayCircle
```

**Root Cause:** `DrawOverlayCircle` used `Resources.GetBuiltinResource<Sprite>("UI/Skin/Knob.psd")` which is not available in modern Unity versions. `_circleSprite` stayed null, so all circle images had no sprite, and the error fired every frame on rebuild.

**Solution:** Replaced with a procedural circle generator:
```csharp
private static Sprite BuildCircleSprite()
{
    const int size = 64;
    var tex = new Texture2D(size, size, TextureFormat.RGBA32, false);
    tex.filterMode = FilterMode.Bilinear;
    var center = size * 0.5f - 0.5f;
    var r = center;
    for (var py = 0; py < size; py++)
        for (var px = 0; px < size; px++)
        {
            var dx = px - center; var dy = py - center;
            var dist = Mathf.Sqrt(dx*dx + dy*dy);
            var alpha = Mathf.Clamp01((r - dist) + 0.5f);
            tex.SetPixel(px, py, new Color(1f, 1f, 1f, alpha));
        }
    tex.Apply();
    return Sprite.Create(tex, new Rect(0,0,size,size), new Vector2(0.5f,0.5f));
}
```
`_circleSprite` is lazily built once and reused. No external asset dependency.

**Files:** `Assets/Scripts/UI/PrototypeRunScreenController.cs`

### R7 — HP Bar Not Visually Decreasing

**Problem:** HP bar fill did not visually shrink when the player lost HP. Text label updated correctly but the fill bar remained at 100%.

**Root Cause:** `Image.Type.Filled` requires a valid sprite to render the fill correctly. The `HpBarFill` image (created procedurally via `new GameObject(...)`) had no sprite assigned, causing undefined fill behavior in some Unity versions.

**Solution:** Added `EnsureBarFillSprite(Image fill)` called from `RefreshHud` each time before setting `fillAmount`:
```csharp
private static void EnsureBarFillSprite(Image fill)
{
    if (fill.sprite != null) return;
    var tex = new Texture2D(4, 4, TextureFormat.RGBA32, false);
    // fill with white pixels...
    fill.sprite = Sprite.Create(tex, new Rect(0,0,4,4), new Vector2(0.5f,0.5f));
    fill.type = Image.Type.Filled;
    fill.fillMethod = Image.FillMethod.Horizontal;
    fill.fillOrigin = 0;
}
```
Applied to both HP and Pencil fill bars.

**Files:** `Assets/Scripts/UI/PrototypeRunScreenController.cs`, `Assets/Scripts/UI/InRunUiBlueprintBuilder.cs`
