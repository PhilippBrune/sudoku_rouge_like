# JIRA-0020 — Class XP & Level Progression Overhaul

**Created:** 2026-03-11

## Summary

Simplify and overhaul the Class XP & Level Progression system: new per-puzzle XP formula, new `round(50 × level^1.5)` level curve (max 40), stat bonuses at milestone levels, and Class Select + game-over UI updates to display bonuses and next unlock.

---

## Requirements

### R1 — XP Formula: Simplified Per-Puzzle Calculation

**Problem:** Previous formula used boardSize, modifierCount, difficultyMultiplier, bossMultiplier, and perfectMultiplier in a complex chain. Hard to communicate to players and tuning was opaque.

**Solution:**
```
BaseXP = 40 + 10 × stars
Boss puzzle: BaseXP × 2
Perfect Solve Bonus: +25 flat
```

**Files:** `Assets/Scripts/Economy/XpService.cs`

Before:
```csharp
var baseXp    = BaseXpForBoardSize(boardSize);  // 50/75/100/150/200 by size
var finalXp   = (int)Math.Round(baseXp * diffMult * modMult * perfectMult * bossMult);
```

After:
```csharp
var baseXp    = 40 + 10 * stars;
var puzzleXp  = isBoss ? baseXp * 2 : baseXp;
var finalXp   = puzzleXp + (perfectSolve ? 25 : 0);
```

`XpBreakdown` struct simplified: removed `DifficultyMult`, `ModifierMult`, `PerfectMult`, `BossMult`; added `Stars`, `PuzzleXp`, `PerfectBonus`.

`BuildDisplayText()` updated to show new breakdown.

---

### R2 — Level Curve: round(50 × level^1.5), Max Level 40

**Problem:** Previous curve started at L1=500 XP (too slow for new players) and used a linear+quadratic hybrid that was hard to reason about.

**Solution:**
```
XP_to_next_level = round(50 × level^1.5)
```
Sample thresholds: L1→50, L2→141, L3→260, L5→559, L10→1581, L20→4472, L40→12649.

Max level remains 40; `XpService.MaxPlayerLevel` updated to 40 (was 30).

**Files:**
- `Assets/Scripts/Economy/XpService.cs` — `XpToNextLevel` updated
- `Assets/Scripts/Meta/ClassGardenProgressionService.cs` — `XpToNextLevel` updated

---

### R3 — Stat Bonuses at Milestone Levels

**Problem:** Class levelling had no in-run stat impact; players had no reason to care about level past cosmetics.

**Solution:** Cumulative stat bonuses granted at level milestones (applies to both global and per-class level):

| Level | Bonus |
|-------|-------|
| 3  | +1 Pencil |
| 7  | +2 Max HP |
| 10 | +2 Pencil, +2 HP |
| 15 | +1 Reroll Token |
| 20 | +1 Item Slot |
| 30 | Rare Solver Item (unlock) |
| 40 | Prestige Available |

**New Methods in `ClassGardenProgressionService`:**
- `GetStatBonuses(level)` → `(HpBonus, PencilBonus, RerollBonus, SlotBonus)` — cumulative bonuses up to level
- `GetNextUnlock(level)` → string label for next milestone
- `GetUnlocksInRange(oldLevel, newLevel)` → `List<string>` of unlocks triggered on level-up

**Files:** `Assets/Scripts/Meta/ClassGardenProgressionService.cs`

---

### R4 — GardenProgressionUpdate: Class-Level Data

**Problem:** `GardenProgressionUpdate` only returned global garden level data; callers could not know the per-class level-up result or unlocks triggered.

**Solution:** Added to `GardenProgressionUpdate`:
```csharp
public ClassId ClassId;
public int ClassOldLevel;
public int ClassNewLevel;
public int ClassLevelsGained;
public List<string> ClassUnlocksGranted = new();
```

`ApplyRun` now tracks class level before/after and calls `GetUnlocksInRange` to populate `ClassUnlocksGranted`.

Added debug log: `[XP] Run end — Class:{} XP+{} ClassLv:{}→{} GlobalLv:{} Unlocks:{}`.

**Files:** `Assets/Scripts/Meta/ClassGardenProgressionService.cs`

---

### R5 — Class Select UI: Stat Bonus Format

**Problem:** Class Select showed raw base stats with no indication that levelling increases them.

**Solution:** Stats shown as `HP 10 (+2)` when level bonuses are nonzero; plain `HP 10` at level 1. Next level unlock shown below stats.

Example at level 7:
```
HP 12 (+2) | Pencil 11 (+1) | Slots 2 | Rerolls 1
...
Level 7 | XP 240/346
Next: Lv 10 — +2 Pencil, +2 HP
```

Unlock table updated: removed Lv 5 Passive Tier Up entry (not a stat-bonus milestone).

Added debug log: `[XP] RefreshClassSelectUi — {class} Lv{n} XP:{x}/{total}`.

**Files:** `Assets/Scripts/UI/MainMenuController.cs`

---

### R6 — Game-Over Panel: XP Breakdown + Class Level Progress

**Problem:** Game-over panel only showed raw `XP Gained: +N` with no breakdown or class-level progress.

**Solution:** Panel now shows:
1. `— XP Breakdown —` section using `XpBreakdown.BuildDisplayText()`
2. Per-class level line: `Class Level 5  (72%)`
3. XP bar values: `XP 402/559`
4. Next class unlock: `Next: Lv 7 — +2 Max HP`
5. Global Garden Level with percentage

**Files:** `Assets/Scripts/UI/PrototypeRunScreenController.cs`

### R7 — Tutorial UI: Categorized Modifier Toggles (No Overlap)

**Problem:** All 15 modifier toggles were in a single flat 2-column `GridLayoutGroup`. Bottom UI elements (validation text, modifier description, buttons) overlapped the toggle area.

**Solution:** Replaced flat `GridLayoutGroup` with a `ScrollRect` containing a `VerticalLayoutGroup` content pane. Modifiers grouped into 4 categories with accent-coloured headers:

| Category | Modifiers |
|----------|-----------|
| Global / Negative | Nonconsecutive, Antiknight |
| Line Mechanics | German Whispers, Dutch Whispers, Parity Lines, Renban Lines, Palindrome, Thermo, Between Lines |
| Arithmetic | Arrow Sums, Killer Cages, Difference Kropki, Ratio Kropki |
| Marking / Special | Even/Odd, Fog of War |

Bottom bar (validation, hint, description, buttons) repositioned to `y=0.02–0.26` with no overlap.
Top controls (board, stars, resource, region dropdowns) shifted up to `y=0.67–0.89` to give more vertical space.

**Files:** `Assets/Scripts/UI/MainMenuBlueprintBuilder.cs`
