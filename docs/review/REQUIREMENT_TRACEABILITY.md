## How to read this

- **Code**: where the behaviour lives. `Tagged ×N` = number of `// [REQ: ID]` annotations; an annotation alone is *not* evidence that the behaviour works.
- **Runtime test**: evidence collected in this review. `D##` = diagnostic EditMode test driving the real services ([E2E report §2](E2E_TEST_REPORT.md)); `E##` = observation in the freshly built Windows player ([E2E report §3](E2E_TEST_REPORT.md)); `F##` = fix verification in a fresh build of the fixed tree ([E2E report §9](E2E_TEST_REPORT.md#9-addendum-fix-verification-2026-10-05)); `EditMode` / `PlayMode` = Unity Test Runner run of 2026-10-07; `build B##` = check in the 1.1 player build ([E2E report §10](E2E_TEST_REPORT.md#10-addendum-release-110-2026-10-07)).
- **Automated test**: an existing test in `Assets/Scripts/Tests` that covers the behaviour (result from the 2026-10-01 baseline run; for *Fixed 2026-10-05* rows, from the 2026-10-05 run; for *1.1* rows and tagged rows, from the 2026-10-07 run).
- **Status**: exactly one of `IMPLEMENTED` (implemented *and* verified), `PARTIALLY_IMPLEMENTED`, `BROKEN`, `MISSING`, `CONTRADICTED`, `OUTDATED`, `UNTESTABLE`.
- `UNTESTABLE` is used in two senses, and the *Runtime test* and *Gap / note* columns say which: genuinely not verifiable with current infrastructure (audio, profiler captures, visuals), or **not verified (coverage gap)**: no automated test references the behaviour and this review did not exercise it. A coverage-gap item is *not* claimed to work.
- Requirement text is quoted from the source documents. Several of them contain double-encoded characters ([SPEC-PROC-004](SPECIFICATION_ISSUES.md#spec-proc-004)); these are repaired in the quotes (for example `â†’` is shown as `→`).
